# Workagent: bounded upstream reuse review

**Current integration decision: keep managed-first and reuse the existing Workagent authority, broker, pinned context and PostgreSQL outbox. Do not build an unused runtime receipt abstraction solely to run another fixture; implement the smallest adapter alongside the first authorized, qualified real runtime consumer. Do not install either framework or replace the selected discovery path.** Hermes is the more natural *conditional* Python worker candidate; OpenClaw supplies useful delivery/reconciliation and context-interface designs. Neither supplies Workagent's business authority. These are source-level judgments, not comparative run results.

Integration clarification after accepted baseline `5ae4cbb`: the initial fixture-only RuntimePort recommendation below was superseded by the later [runtime access audit and integration decision](../RUNTIME_ACCESS_AUDIT.md#source-review-integration-decision). This correction makes that precedence explicit; upstream pins, citations, license findings and historical non-execution evidence are unchanged. No new runtime implementation, provider call or framework selection is commissioned here.

## 2. Component decisions: reuse / adapt / build

Complexity below is relative integration/maintenance judgment, not an elapsed-time estimate. “Reuse later” requires a separately authorized contract spike.

### Runtime and tool adapters — adapt a boundary, not the application

**Hermes:** [`AIAgent.__init__`, `run_agent.py:261–303`](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/run_agent.py#L261-L303) accepts session identity, toolsets, callbacks, iteration/time budgets, and flags to skip context, memory and background review. [`TurnFacadeMixin.run_conversation`, `agent/turn_facade.py:22–91`](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/agent/turn_facade.py#L22-L91) includes durable turn admission; it is not just a stateless completion function. [`ToolRegistry.dispatch`, `tools/registry.py:887–915`](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/tools/registry.py#L887-L915) executes handlers and converts exceptions to tool errors. A handler bridge could call Workagent's typed `Broker.call`; registry membership is not Workagent authorization.

**OpenClaw:** [`runEmbeddedAgent`, `src/agents/embedded-agent-runner/run-orchestrator.ts:110–140`](https://github.com/openclaw/openclaw/blob/c074824a27c96d3983043f9eeb33823cd1772d8c/src/agents/embedded-agent-runner/run-orchestrator.ts#L110-L140) binds lifecycle/plugin generations. [`createOpenClawTools`, `src/agents/openclaw-tools.ts:93–145`](https://github.com/openclaw/openclaw/blob/c074824a27c96d3983043f9eeb33823cd1772d8c/src/agents/openclaw-tools.ts#L93-L145) draws on secrets snapshots, session agents, workspace and plugin state. This is not a small isolated agent SDK. Its separable [`@openclaw/ai` package](https://github.com/openclaw/openclaw/blob/c074824a27c96d3983043f9eeb33823cd1772d8c/packages/ai/package.json#L1-L72) declares provider/streaming exports, not Workagent lifecycle guarantees; adding it now would create a different provider route.

**Call:** defer a new port until a concrete real consumer is authorized; then adapt the existing application boundary minimally. If managed-first later fails a *demonstrated required contract*, assess a pinned Hermes worker process before importing Hermes into FastAPI. Python affinity lowers glue cost, but callbacks, global/plugin state, credentials and lifecycle isolation make it **medium-high**, not a drop-in. Full OpenClaw embedding is **high** and adds a Node runtime. A process boundary permits separate dependencies, restricted environment and termination; it does not itself provide workspace security or safe retry. Do not copy either model loop or layer one behind a managed loop.

OpenClaw [`resolveWorkspaceSkillPromptEntries`, `src/skills/loading/workspace-skill-loader.ts:503–577`](https://github.com/openclaw/openclaw/blob/c074824a27c96d3983043f9eeb33823cd1772d8c/src/skills/loading/workspace-skill-loader.ts#L503-L577) performs source selection, runtime eligibility and freshness checks. Hermes [`cron/scheduler_tick.py:18–119`](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/cron/scheduler_tick.py#L18-L119) file-locks ticks, advances recurring schedules before execution and submits guarded pool work. **Call:** neither should own Workagent schedules. Hermes [`BaseEnvironment`, `tools/environments/base.py:219–273`](https://github.com/NousResearch/hermes-agent/blob/f97608f178d1ffeca59860195ab7da295f7c8e5f/tools/environments/base.py#L219-L273) separates execution/cleanup from backend spawning. **Call:** no sandbox is needed for the current typed, fixture-only tools. Local/SSH execution is not intrinsically a security sandbox; provider API names do not prove containment. Do not expose shell/browser/raw database access to bypass `Broker`.

## 3. Non-transferable ownership

Workagent retains **Space/workspace scope; current principal and source access; standing permissions and exact grants; immutable revisions and human edits/acceptance; command replay; action reconciliation; completion evidence; cost attribution**. Bind runtime session/turn/child identity to these application records, not vice versa. Broker checks stay at dispatch and commit, including access generation, current fence and budget. Runtime callbacks, summaries, channel pairing, “done” text and usage estimates are observations—not permission, acceptance or verified completion. Compaction and resume cannot expand scope. Runtime-reported usage needs run/attempt attribution and an explicit unknown/unpriced state until pricing or billed evidence is available.

## 4. Deferred adapter requirements, not a fixture-only next implementation

The initial source review proposed a typed `RuntimePort` receipt bridge exercised only by synthetic fixtures. **That immediate-build recommendation is superseded.** Keep the tested application machinery; do not add `backend/workagent/runtime_port.py` or a parallel receipt framework without an authorized concrete consumer.

When a separately authorized real runtime lifecycle is ready to consume the boundary:
- Add only the submit, inspect/reconcile and cancel adaptation that the chosen consumer actually needs, with explicit `accepted`, `rejected`, `unknown` outcomes. Do not invent endpoints or assume idempotency capabilities before observing them.
- Bind application submission key, run/fence, bundle/context hashes and returned runtime session/turn IDs through the existing domain/dispatch transaction path. Preserve an unknown acknowledgement; inspect before retry, and remain unresolved when inspection cannot settle it. A stream ending is not permission to create a replacement session.
- Keep typed tool callbacks behind `Broker.call`, `runtime_config.assemble_context` and `BundleLoader`. Dedupe callbacks and reject late/stale fences. Runtime terminal text is not action verification or human acceptance.
- Use existing PostgreSQL/fixture fault tests for local contract regressions, then obtain actual consumer evidence for session/recovery behavior. Fixture tests cannot qualify provider lifecycle semantics. Attribute usage with explicit unknown/unpriced states; do not invent zero cost.

This preserves the useful unknown-delivery and session/tool-callback distinctions without adopting upstream state owners. No gateway, cron, fan-out, shell-tool or framework dependency is authorized by this review. A project/secret reference, bounded inference/spend grant, approved synthetic-data route, verified SDK/model/API access and trace controls are still required before **one managed-first lifecycle**. The previously successful subscription request was operator-assisted and its one-call allocation is consumed; it neither selects a fallback nor authorizes another dispatch. `MODE=live` remains fail-closed until that separate work is qualified.
