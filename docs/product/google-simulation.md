# Google simulation and integrated exchange

The default application keeps Google **off**. The candidate integration adds an explicitly enabled local simulation to the actual authenticated HTTP service, Workspace/PostgresStore transactions and mounted exchange UI. It is uninstalled and has no real Google account, OAuth consent, account discovery or production-endpoint fallback. Full authorized Google Sheets/Docs integration and the B04/B05 roadmap remain open, including native OT, presence, comments and history.

Parent can enable this candidate with the exact runtime setting `WORKAGENT_GOOGLE_SIMULATION=local-only`. Any other value leaves it disabled. `startGoogleSimulation({workspace, simulation: true})` explicitly starts an ephemeral `127.0.0.1` simulator; importing the module or constructing a disabled exchange starts no listener. All credentials are generated synthetic values held server-side, excluded from app state, logs and responses. The app advertises **Simulated Google — local only**, with Simulated Alice and Simulated Bob and separate file ACLs. Remote simulated files are volatile across service restart; the app journal and historical receipts persist in PostgreSQL.

In Work actions, choose a simulated account, preview explicit Sheets tab/ranges, then separately adopt the immutable preview. Adoption creates new native work with server-bound provenance and an explicit Open action; it never saves or replaces current work. For a native document, preview captures the actual editor commit/export snapshot without saving, shows the exact title/text and plain-text policy, and requires separate confirmation. Rich content refuses visibly. Delivery uses the adapter's create → blank read → required-revision insert → authoritative readback. Simulated IDs are text, never real Google document links. Messages remain visible outside collapsed Google details and outer tools; per-work previews, pending commands and receipts survive navigation. Remount/status refresh performs reads only.

## Supported contract

`apps/workagent-server/src/google-adapter.mjs` exports:

- `createGoogleAdapter({credentials, timeoutMs?, maxResponseBytes?})`: native fetch to fixed official Sheets/Docs/OAuth origins. Credentials are supplied by a trusted server broker; no lookup, environment fallback or URL/transport override. Construction is not connection verification. Live calls are implemented but unqualified and unused in this stream.
- `createSimulatedGoogleAdapter({origin, credentials, ...bounds})`: only an explicit `http://127.0.0.1:<port>` origin and `SIMULATED_...` credential values. Real credential-shaped values are refused before any request. Live construction refuses synthetic values. Only server bootstrap selects this constructor; request bodies cannot select mode, origin or credentials.
- `previewSheet({spreadsheetId, ranges:[{sheetTitle,range:'A1:E2'}], previewId?})`: one GET with `includeGridData=true` and repeated quoted bounded A1 ranges, with no fields mask. One rectangle per named tab, up to 20 tabs, 10,000 rows/200 columns and 50,000 selected rectangular cells total; response cap 4 MB and existing 4M-character native workbook validator apply. Returns a validated native workbook preview, selected ranges, observation time, request ID, calculation policy and explicit simulation/live provenance. Source coordinates, strings (including leading zeros/formula-like literal text), numbers and booleans survive; missing cells remain absent. No work creation, save or source adoption occurs.
- `prepareGoogleDocDelivery(nativeDocument)`: side-effect-free, validated immutable plain-text action and SHA-256 digest. Nonempty text within native document limits, normal paragraphs and default native page geometry only. The opened plain baseline is derived from the pinned Univer 1.4.0 `DocumentDataModel` applied to the canonical `blankDocument`; exact SDK-added style defaults and the generated terminal `sectionId` are accepted. Normal native typing may add an exact default foreground run: `cl.rgb` is resolved from the pinned SDK `ThemeService` gray.900 (`#1B1C1F`). Only that run field/value or an empty run style is accepted; font, decoration, alternate colors and other authored run fields remain refused. The caller snapshot remains intact; style/resource checks still refuse unsupported content. Rich styles, lists, changed default values, authored paragraph/section properties, nondefault layout, unsupported structures and text Google may strip are refused before create. Text uses LF; Google default appearance differs. No flattening of rich content is presented as faithful export.
- `executeDocDelivery(plan,{operationId,recordEffect,checkAuthority?})`: explicit operation; POST create with **title only**, GET with `includeTabsContent=true`, require exactly one blank editable tab, POST one insertText using `location.tabId` and `writeControl.requiredRevisionId`, then authoritative GET verifies title, tab and exact text including Google's final newline. No `targetRevisionId`, stale-revision bypass or invented Google idempotency key. Returned receipt carries local operation/request IDs, document/tab IDs, required/readback revisions and provenance. Simulation has no real Google document link. Opaque revision IDs are never ordered numerically.

`credentials` fields: `accessToken`, optional `expiresAt` (epoch milliseconds), and optional `refreshToken/clientId/clientSecret` for one bounded refresh per import/delivery operation. Refresh POST uses the OAuth form contract. Missing tokens fail before dispatch; expired tokens and refused reads get at most one refresh. Provider writes never automatically repeat, including after 401. The integrated authority callback also runs immediately before a write, after any asynchronous refresh. `invalid_grant` and continued 401 fail closed. There is no generic read/write retry loop; scope/permission errors never trigger refresh.

`GoogleExchange` stores connections, previews and operations under `googleSimulation` in the existing Workspace JSONB row, using the actual `PostgresStore` read/transaction interface. No schema migration or separate Map journal is used. The authenticated workspace owner, synthetic account, connection generation, work preconditions, source snapshot hash and exact action digest bind confirmation. Connect/disconnect/switch advances a durable generation; owner-only exchange does not grant shared peers source or delivery authority. Client principal/account/source claims cannot authorize themselves.

Admission reserves the operation and consumes its preview in one transaction. Each create/update intent, request ID, known document ID, stage and outcome commits before the next provider operation; HTTP never runs under the workspace lock. Authority is checked again between stages and immediately before writes. A failed pre-dispatch journal commit causes no external write. Durable dispatch intents are conservatively unknown until verified readback is also committed. A failure to store the final result leaves the preceding unknown intent, not a success. Current authority is checked before new confirmation or duplicate-command handling; explicit status reads retain earlier own-work receipts after disconnect/switch.

One preview admits at most one delivery even with a different command ID. Exact duplicate commands return their stored receipt/status; conflicting payload reuse refuses. Reserved, completed, refused and unknown operations never resume or redispatch automatically, including after a new service instance or remote simulator reset. An unresolved reservation without a dispatch record is also not restarted. Receipts are historical readback evidence, not a claim that volatile remote files survived restart. There is no automatic reconciliation/repair route. The client stores the exact pending action before its request and uses a version fence to avoid overwriting another tab's newer action state. Receipt recovery uses GET only, including after local edits. An explicit retry first checks for an admitted receipt; if none is found, it revalidates the original native snapshot and principal, account/connection generation, work revisions, navigation generation and editor identity before sending the original operation ID. A stale action requires a fresh preview and confirmation; it cannot resend the old text. Recovering a verified or unknown receipt never saves or replaces a newer native draft. New operations retain an admission `createdAt` in the existing journal, including reserved/not_started outcomes without a stage timestamp. Receipt arrays have no chronological ordering contract. The client first matches the exact pending operation (then its unique preview), otherwise refreshes the active stored receipt by operation ID. Cold selection uses admission time or legacy `recordedAt`; missing chronology and timestamp ties cannot bury unverified outcomes behind success. IDs only stabilize display ties, never imply chronology. Each returned receipt is retained in the existing principal/work-scoped browser form independently of active selection; state reads merge receipts by operation ID. An authoritative same-operation update replaces its prior outcome, while a different successful operation cannot resolve an earlier unknown. This cache survives preview refusal, connection changes and remount even if the next receipt read fails. All unverified actions remain in the visible notice and App notice callback, even while a later action is verified or a new preview is open; an unmatched pending request remains unresolved. Legacy receipts are retained without timestamp backfill or migration.

## Refusals and uncertainty

Sheets formulas are refused even when a cached effective value exists; effective-only cells are refused. No cached formula output becomes verified/current data. Authored cell formatting (including dates), rich text, merges, charts, validation/checkboxes, notes, links, named ranges and unsupported structures are refused. Unselected cells/tabs and layout are explicitly outside the preview, not silently claimed as imported. Broader formula/format coverage remains future work.

Errors expose fixed codes and bounded IDs/status, never provider response text, headers or tokens. Reads distinguish definitive refusals from transport/5xx transient failure. 429 is a reported quota refusal; callers may propose a later read but no retry happens automatically. Redirects, host changes, malformed/oversized responses and timeouts fail closed. Transport/5xx or unreadable success after a write is **unknown**, never fabricated success/refusal. A successful create followed by any failure remains a partial/unknown delivery, with `callOutcome` describing the later call separately; the created blank doc is not automatically deleted. A lost create response may leave no document ID: retain its local request/operation IDs and reconcile manually. Google does not promise lookup by these local IDs, so a lost create cannot be safely recovered by automatic replay. Known-document readback is possible using the retained Google ID, but this increment exposes no automatic repair/resend method.

HTTP tests independently assert metadata-only default Sheets GET, blank Docs create despite supplied content, tab-aware GET, missing reader revision, stale revision **400**, atomic invalid batch refusal, server read-only enforcement, exact request counts, state after disconnects, revoked grants, no secret-bearing logs, oversized-response/redirect refusal and readback mismatch. They cannot establish Google's consent/verification, real quotas, actual account permission behavior or live interoperability. A simulator agreeing with the adapter is contract evidence only; Parent owns independent risk review and eventual authorized live qualification.
