## 1. Existing observation contract (not a new timestamp field)

- **`current_outcome_at` does not exist** in tracked backend/contracts or the generated OpenAPI DTOs. `ResponsibilityPlan.current_outcome` is prose; `ResponsibilityLifecycle` adds outcome status/evidence and dependency observations, but no prose timestamp (`backend/workagent/responsibility_models.py:36-41,68-85`). The existing read projection is `historical_observation: {text, observed_at?}` (`backend/workagent/work_event_models.py:73-84`; generated `contracts/src/schema.d.ts:2808-2813`).
- Snapshot text comes from the current `responsibility_lifecycle.current_outcome`; only its timestamp comes from the left-joined `work_responsibility_observations` row. The table does **not** store a historical text body (`backend/workagent/work_snapshot.py:131-142`). It is a latest-note projection, not an observation-history collection.
- Migration047 creates one `(workspace_id, assignment_id, outcome_hash, observed_at)` row and deliberately backfills existing prose with **NULL time** (`backend/migrations/047_work_events.sql:47-54`). On subsequent assignment writes, initial insertion uses `transaction_timestamp()`; conflict updates change time only when the MD5 of `current_outcome` changes (`:102-110`). Thus time means **the transaction recording this changed text**, not when the work was performed, checked, or verified. Identical re-recorded text does not advance it; unrelated plan/status/dependency changes do not advance it; legacy NULL remains NULL until text changes.
- Verified migration inventory through current head: 001–057, including inspection of all later 048–057 files for affected identifiers and function replacements. None replaces `work_event_capture`, the observation table, or `general_publication_text`; none adds `current_outcome_at`. Migration048 merely compares `current_outcome` to a saved successor binding (`backend/migrations/048_run_checkpoints.sql:211`). Migration056 replaces artifact visibility, not observation semantics (`backend/migrations/056_file_alias_visibility.sql:4-18`). DTO/OpenAPI field inspection independently confirms no later timestamp/revision-basis addition.
- **Never substitute assignment timestamps, snapshot `checked_at`, or fetch time.** Snapshot `checked_at` is read time (`backend/workagent/work_snapshot.py:146-156`), not observation time.

## 2. Revision basis and authorship: retain uncertainty

- `HistoricalObservation` has no artifact/revision ID, content hash, author, or source run. The observation table's MD5 is a **prose change detector**, not an artifact hash or revision proof (`047_work_events.sql:47-54,106-110`; `work_event_models.py:73-75`).
- Exact dependencies and evidence **do exist elsewhere**: dependency `expected_version`, `observed_version`, `content_hash`, `changed`; lifecycle `outcome_evidence`; run-binding observations/work versions (`responsibility_models.py:13-22,68-85,114-128`). Agent advancement can retain run/attempt/evidence alongside a new plan (`backend/workagent/responsibility_action.py:258-277`). Do not claim the whole service lacks revision evidence.
- Those fields are not a universal immutable basis for this prose. Dependency refresh replaces lifecycle observations and marks `needs_review` without rewriting the note (`backend/workagent/responsibilities.py:350-385`). The existing regression explicitly expects a new human artifact revision while the historical observation remains unchanged (`backend/tests/test_work_events_pg.py:301-319`; inspected, not executed here). Current artifact revisions are separately projected (`work_snapshot.py:89-97`). Therefore do not attach current artifact revision IDs to old prose or imply it describes today's saved output.
- Nor is this always the agent's own wording: owner activation/update accepts `ResponsibilityPlan` (`responsibilities.py:205-241,245-277`), and the runtime writes admission/settlement explanations (`backend/workagent/responsibility_execution.py:249-265,290-304`). **Recommend “Latest recorded note” / “Recorded responsibility note”**, not unconditional agent authorship.

## 4. Existing retained explanation and preview behavior

- Conversation list preview is exactly the last sequence-ordered message's stored `text[:240]`; `updated_at` is that message's time (`backend/workagent/conversations.py:84-87,106-109`). The DTO only exposes that string, not an outcome discriminator (`backend/workagent/models.py:490-504`). It is not generated from `current_outcome` or reconstructed by the UI.
- Alpha publication: `answered` uses decision text; blocked/wait/step/budget stops use bounded broker reason; other outcomes preserve generated explanation plus `\n\nExecution status: ` and broker reason (`backend/workagent/composition.py:296-313`). Python and SQL intentionally agree (`backend/migrations/017_general_alpha.sql:3-9`; `021_alpha_stop_display.sql:11-22`). Publication stores that text in immutable messages (`backend/workagent/products.py:525-552,558-561,579-582`; `backend/migrations/009_conversations.sql:41-42`). Therefore the suffix can appear in a short preview, or be absent from a long preview; string stripping would discard trusted limitation information and cannot reliably distinguish model text.
- **Retained explanation already exists**: `TurnState.explanation: ExplanationReadback` has text, attempt ID, final phase, `authority='model_explanation_not_verification'`, and `published` (`backend/workagent/general_alpha_models.py:45-51,61-73`; generated `contracts/src/schema.d.ts:4551-4579`). Readback validates the completed final receipt and binds publication by run/attempt (`backend/workagent/products.py:19-29`). `published` establishes matching assistant publication, not byte identity between full explanation and displayed text.
- Typed outcome/limitation ingredients also exist on turn detail: `adaptive.outcome`, step reason/verification, `TurnState.state/reason`, retained result (`general_alpha_models.py:20-42,61-73`). `adaptive_readback` avoids advertising answered/completed before publication (`products.py:32-66`). **Do not invent a second explanation store or treat `replied`/`answered` as verified goal completion.**

## 5. Minimal additive proposal — NOT implemented

1. Preserve immutable messages, receipts, current `last_message_preview`, and old publication rules. No backfill/rewrite of historical prose or times.
2. Add an optional **read-only `Conversation.preview` DTO** (proposed name, absent today), bound to the exact latest message: `{message_id, run_id, author_kind, text, text_source, outcome}`. `text_source` is a discriminator such as `stored_message | retained_explanation`; `outcome` is nullable, typed metadata `{state, adaptive_outcome?, reason, explanation_authority?}` using existing turn enums and broker reason. This is a projection, not new execution state or verification authority.
3. For an assistant message, use retained explanation only after exact run/attempt/publication binding; keep answered decision text and canonical stop reasons as appropriate. Surface trusted limitations separately and visibly; never swap in optimistic prose alone. For human/system messages, missing/mismatched receipts, or historical unsupported cases, preserve stored-message preview and nullable outcome. Never borrow an earlier assistant result for a newer message. Label retained prose as explanation, not verified fact.
4. Reuse existing detail DTOs first; add only the bounded list projection needed to avoid fetching full detail per row. Regenerate clients and add focused tests for legacy/NULL time, unchanged note on new artifact revision, human/runtime authorship, failed snapshot, long/short explanation, answered/stopped/needs-validation, and exact message/run/attempt mismatch.
5. **Defer explicit note revision-basis/author provenance** until captured atomically with note creation, using new optional fields with historical unknown values. Do not infer these from mutable lifecycle observations. A `current_outcome_at` alias alone adds no stronger truth than existing `observed_at`.
