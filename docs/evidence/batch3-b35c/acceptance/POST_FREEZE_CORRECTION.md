## Changed behavior

### F1 — terminal responses no longer loop as running

The adaptive selection, new-final and prepared-final paths distinguish authenticated terminal failures from pending or indeterminate results. Exact request/count/response identity, current capability/fence/context/source and settled prior/native effects are checked before durable `partial` / `blocked` state and a blocked checkpoint are stored. Saved work, provider events, request identities and cost accounting remain unchanged. No assistant success message, refund, duplicate dispatch or automatic retry is invented.

Parser `malformed` is not synonymous with external termination. Nine reviewed output-shape issue codes qualify only after authenticated completed-response parsing. Envelope/correlation/usage errors, unknown status, invalid JSON and unreviewed issue codes remain indeterminate. Worker, checkpoint and collector share this distinction. Existing conservative next-admission constraints remain; this is not automatic continuation of failed provider work.

### F2 — invalid targeted creates remain denied without stranding the workflow

A hash-invalid `files_create_draft` in a targeted run is retained through the existing exact, material-free selection-rejection mechanism. It is not executed with a repaired hash, promoted to file authority or swallowed by a blanket permission-error handler. Bounded subsequent selection can choose an authorized action. Current revocation and unknown-effect exclusions still deny; valid targeted patch behavior and protected human material are preserved.

### F3 — useful partials and explicit operational review

New `evaluation/post_freeze_packets.py` is separate from the frozen campaign. It permits authorized collection of safely observed partial work without treating explanatory `unresolved` text as an external unknown. It verifies exact receipts and native outcomes, preserves partial status, and labels conversation-current context separately from exact producer-run revision references. Readback is not browser-download evidence; proposals remain proposals and grading remains unperformed for these synthetic controls.

Operational helpers require explicit accept or retain-current decisions, justification, exact base/proposed/current hashes, protected text, ordinary removal acknowledgement and CAS, then read back the result. Dependent-transition checks reject pending decisions and absent, withdrawn, wrong-artifact, stale or incorrectly keyed receipts across all authorized pages. Scripted review is not measured human effort.

**Integration boundary:** this is a tested future-call helper, not a modification or replacement of the frozen controller. Future callers must invoke the review gate immediately before their action and retain/recollect the output packet. It does not make an arbitrary later action atomic; that action must still enforce current authority and CAS. No new live campaign or browser UX improvement is claimed.
