# Batch3 tool/memory interface — B3.0a gateway handoff

Scope: capability execution/accounting only. B3.0b owns exact-version files/exports; later cards own memory/connectors/compute/UI. No private credentials, connector consent, memory mutation, file transform or browser UI has been installed by this card. Runtime activation is separate from source availability.

## Canonical contracts and Claude handoff

Generated by `backend/export_contracts.py` / `npm --prefix contracts run generate`:

- `contracts/capability-descriptor.schema.json`: `CapabilityDescriptorV2`.
- `contracts/capability-registry-v2.json`: reviewed native adapter descriptors, not grants.
- `contracts/tool-grant.schema.json`: owner-installed `ToolGrantV1`, NEVER a model/HTTP command.
- `contracts/tool-call.schema.json`: strict `ToolCallV1`, worker-internal only.
- `contracts/tool-observation-v1.json`: `ToolObservationV1`.
- `contracts/openapi.json`, `contracts/src/schema.d.ts`: actual authenticated read DTOs.

Endpoints use the existing private local bearer, request/schema headers and nonenumerating errors:

| Method/path | Meaning |
|---|---|
| GET `/v1/workspaces/{workspace_id}/capabilities?run_id={run_id}` | Installed descriptors with this run's permission status. `run_id` is required. |
| GET `/v1/workspaces/{workspace_id}/runs/{run_id}/tool-attempts?limit=50&after={attempt_id}` | Bounded page, maximum100, stable attempt-ID ordering; `next_after` is null at end. |
| GET `/v1/workspaces/{workspace_id}/tool-attempts/{attempt_id}` | Current-authority checked attempt detail. |

There is **no execute/install/grant/accept endpoint**. `not_installed`, `needs_consent`, `blocked_by_scope`, `temporarily_unavailable` and `available` describe different conditions. Do not interpret a descriptor, readOnlyHint, output text, or zero marginal-dollar reservation as permission. No unavailable descriptor contains resource titles or credentials.

## Worker boundary

`CapabilityBroker(service, WorkerCapability).call(ToolCallV1)` validates the exact registered input model, current run/lease/source/runtime/generation, matching installation and exact grant pins, privacy/effect/egress scope, expected work version, then atomically reserves capacity/money. Model arguments cannot supply a principal, grant, effect, credential, acceptance flag, budget or mutable run generation.

Initial adapters: `context.read`, `files.inspect_json`, `research.fetch`, `capabilities.discover_legacy`, `procedures.load_legacy`, `legacy.get_assignment`, `legacy.get_artifact`. They call existing hardened/scoped implementations. Public fetch retains its credential-free subprocess, numeric-address/TLS pinning, public-HTTPS-only policy and wall-clock/body bounds. No shell or arbitrary dynamic adapter loading exists.

The existing `Products.stage_general_product` loop uses the gateway when a ToolGrant is present; no parallel agent loop exists. Legacy Broker calls in an opted-in run are also routed through the gateway. Revocation/absence of a matching pin does not fall back to legacy execution. Other operations in an opted-in run remain unavailable until their reviewed adapter is implemented; reply/stop are decisions, not adapter effects. Runs without a ToolGrant retain their frozen historical catalog and existing Wasm/proposal/receipt policy. Wrapped discovery reports current permission rather than legacy hints. Existing historical catalog files are unchanged.

The broker records immutable input scope hashes (run configuration, canonical scope and existing source/artifact fingerprint), output hashes, implementation/schema pins, bounded output, timestamps and costs. Native calls run outside DB transactions. There are reservation, immediate pre-I/O, post-I/O and downstream-consumption fences. SQL-backed `tool_run_available` and the shared Service check prevent revoked tool observations from entering subsequent model requests, staging or publication. Existing receipt staging and run checkpoints retain the same run/phase identity; the observation alone cannot accept or publish a draft.

A committed dispatch is never blindly resent. A completed observation may be reused by a newly fenced current worker. An abandoned reservation or dispatched-but-unobserved attempt remains held/unresolved; this phase does not claim automated reconciliation. Late responses after cancellation, generation/ACL/grant/installation changes or lease expiry settle costs only; output/hash/source refs are removed. A receipt capability does not revive continuation authority.

## Installation and accounting

Additive migration `053_capability_gateway.sql` follows accepted052. Owner-only installations/accounts/grants are immutable except explicit disable/revoke flags. `policy.install` validates exact current run/scope/principal/pins and reads the committed grant back. The runtime role cannot INSERT authority or directly mutate attempt/cost history. Existing runtime readers receive SELECT privileges during upgrade; fresh DB provisioning is not the only supported path.

`tool_budget_accounts` has finite category quotas for local_compute, search, extraction, rendering, connector and child. Parent/child work must reuse the same account ID, not mint a fresh allowance. The current adapters reserve one call and report elapsed/CPU measurements; isolated millisecond-budgeted compute adapters are successor work.

Paid tool accounts point to an **existing** provider grant. Reservations share the existing project advisory lock and `responses_budget_grants` lineage, including `responses_budget_carry`, historical model dispatch reservations and uncertain liabilities. A guard on existing model dispatches enforces the other direction: model calls cannot consume money already reserved by tools. Zero-priced local work still consumes finite category capacity. Settlement is append-only and never refunds a reservation or resets historical money. Model-only calculated cost is separated from combined unknown cost; billing is never synthesized.

The gateway does not activate a product allowance or change the retained100USD owner ceiling. B3.0a uses only disposable synthetic fixtures and controlled transports, with zero paid product calls. Development/review-agent costs are outside the product ledger and are not measured here.

## Successor integration rules

B3.0b must extend this boundary, not add another broker or original-file store. Implement typed file/version refs using the existing049/050 documents/originals; add resource resolution in `policy.authorize` (initial run-context adapters deliberately reject model-supplied file refs). Add reviewed adapters, output models, category reservation and effect-specific current-authority checks; extend the opted-in composition/SQL selection allowlist together. Inert draft outputs require existing proposal CAS and human acceptance where material; never call the private legacy adapter target as an authorization shortcut.

Implementation pins include gateway/policy/model/source bytes and migration053. Source/schema drift fails closed; a changed reviewed implementation needs an explicit new version/installation and compatible run grant. Do not overwrite an installed version to make old grants pass. No hot-reload claim: restart the owned development worker on coherent source before activation. Disable is rollback; no destructive down migration, historical refund or installed-data maintenance was performed.
