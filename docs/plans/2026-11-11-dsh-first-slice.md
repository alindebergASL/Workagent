## Outcome and architecture

The full slice is one fictional workshop responsibility: two concurrent DSH
children compare venues, read local source fixtures and compute a CSV budget,
then produce a sourced editable recommendation. A changed constraint reaches
the actual workers; reopening the new browser client restores work and human
edits. A scheduled continuation updates the same responsibility. A dispatched
fake effect with a lost acknowledgement stays unknown across restart and is
never dispatched twice. Native provider identities, replay facts and usage are
retained exactly, including auxiliary inference. This entire outcome remains
the acceptance target beyond the first checkpoint.

Use the real DSH 0.2.2-rc.1 release, source identity
`66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`, through exported Cordis plugins and
SessionController. Prefer a small set of published, locked release packages
after comparing their shipped source/maps with this checkout; do not install
the all-product CLI graph merely to launch the host. DSH owns the loop, tool
execution, sessions, children, persistence and observation. A curated Workagent
host composition owns a deterministic provider adapter and narrowly scoped
fixture tools. No replacement loop or SDK-shaped mock engine.

Node 24.22.2, pnpm 11.28.5, ESM JavaScript with Node's test runner keep this
checkpoint small. A new plain browser client and loopback HTTP bridge can follow
once the host boots. Product revisions, human edits, constraint versions and
effect identities belong outside the tool-writable workspace, separate from
DSH session logs. No existing Workagent or nanoMuse UI is imported.
